Normalized Relational Schema (3NF)

The database is structured in Third Normal Form (3NF) to eliminate data redundancy and preserve integrity across transactions, line items, products, customers, and commercial regions.

orders (Header Table)
  • order_id (INT, PK, Auto-Inc)
  • order_number (VARCHAR 60, Unique, Index)
  • customer_id (INT, FK -> customers)
  • region_id (INT, FK -> regions)
  • order_date (DATE, Index)
  • payment_method (VARCHAR 50, Index)
  • order_status (VARCHAR 50, Index)
  • total_amount (DECIMAL 12,2)
order_items (Line-Item Table)
  • order_item_id (INT, PK, Auto-Inc)
  • order_id (INT, FK -> orders, Cascade)
  • product_id (INT, FK -> products, Index)
  • quantity (INT, Check > 0)
  • unit_price (DECIMAL 10,2)
  • discount_rate (DECIMAL 5,4)
  • total_price (DECIMAL 12,2)
products
  • product_id (INT, PK)
  • product_code (VARCHAR 50, Unique)
  • product_name (VARCHAR 150)
  • category_id (INT, FK -> categories)
  • unit_price (DECIMAL 10,2)
  • cost_price (DECIMAL 10,2)
customers
  • customer_id (INT, PK)
  • customer_code (VARCHAR 50, Unique)
  • first_name, last_name (VARCHAR 100)
  • email (VARCHAR 150)
  • segment (VARCHAR 50, Index)
  • city, country (VARCHAR 100)
regions & categories
  • region_id (INT, PK)
  • region_name (VARCHAR 100, Unique)
  • category_id (INT, PK)
  • category_name (VARCHAR 100, Unique)
  • description (VARCHAR 255)
Executive KPI Mathematical Formulations
KPI Metric Mathematical Formula Safe Boundary & Zero Division Handling
Total Revenue ∑ (Order_Items.total_price) where status ∈ ('Completed', 'Shipped') Coalesced to 0.00 via COALESCE(SUM(...), 0.0)
Total Orders COUNT(DISTINCT orders.order_id) Evaluates to 0 if zero records match filter.
Average Order Value (AOV) Total Revenue / Total Orders If Total Orders == 0, returns 0.00 to prevent division-by-zero errors.
YoY Growth % ((Rev_Current - Rev_Prior) / Rev_Prior) × 100 If Rev_Prior == 0 and Rev_Current > 0, yields +100.0% baseline growth. If both are 0, yields 0.0%.
Revenue Share % (Category_Rev / ∑ All_Category_Rev) × 100 Window function SUM(revenue) OVER () safely returns 0% when empty.
Customer Segmentation Rules

Customer tiering is dynamically calculated based on realized spending during the evaluated analytical period:

High Spending (VIP Tier)
Lifetime Spend ≥ $5,000.00

Represents enterprise corporate buyers and high-frequency repeat clients. Highest priority for account management and personalized retention.

Medium Spending (Core Spender)
Spend Between $1,500.00 and $4,999.99

Core loyal consumers who order regularly throughout the year. High conversion candidate for volume discounts.

Low Spending (Casual / Introductory)

Data Quality & Cleaning Pipeline
  1. Header Normalization: Fuzzy matches column headers to target schema (e.g. order_id, invoice_no, transaction_id → order_number).
  2. Deduplication Audit: Evaluates duplicate transaction combinations. Flags and deduplicates identical lines while keeping an audit count.
  3. Date Standardization: Uses Pandas coercion to convert diverse dates (e.g. MM/DD/YYYY, DD/MM/YYYY, ISO strings) to standard YYYY-MM-DD. Unparseable dates are logged to the rejection table.
  4. Numerical Bounds Checking: Enforces quantity > 0, unit_price > 0, and scales percent discounts. Invalid numerical values trigger row rejection with clear audit reasons.
  5. Non-Destructive Review: Staged data is never committed to database without stakeholder approval via the "Commit Cleaned Records" button.
Advanced SQL Analytical Patterns

The platform implements enterprise-grade SQL patterns designed to showcase Data Analyst competence:

Calculates time-series trajectories by comparing monthly revenue against the comparable month of the prior calendar year:

WITH monthly_sales AS (
    SELECT
        SUBSTR(o.order_date, 1, 7) AS year_month,
        ROUND(SUM(oi.total_price), 2) AS current_revenue
    FROM orders o JOIN order_items oi ON o.order_id = oi.order_id
    GROUP BY SUBSTR(o.order_date, 1, 7)
)
SELECT
    year_month,
    current_revenue,
    LAG(current_revenue, 12) OVER (ORDER BY year_month ASC) AS prior_year_revenue,
    ROUND(((current_revenue - LAG(current_revenue, 12) OVER (ORDER BY year_month ASC)) 
           / LAG(current_revenue, 12) OVER (ORDER BY year_month ASC)) * 100.0, 2) AS yoy_pct
FROM monthly_sales;

Ranks commercial territories without gaps in ranking sequence while computing percentage contribution to company-wide gross sales:

WITH regional_totals AS (
    SELECT r.region_name, SUM(oi.total_price) AS territory_revenue
    FROM regions r JOIN orders o ON r.region_id = o.region_id
    JOIN order_items oi ON o.order_id = oi.order_id
    GROUP BY r.region_name
)
SELECT
    DENSE_RANK() OVER (ORDER BY territory_revenue DESC) AS sales_rank,
    region_name,
    territory_revenue,
    ROUND((territory_revenue * 100.0) / SUM(territory_revenue) OVER (), 2) AS global_share_pct
FROM regional_totals;

Setup & Execution Instructions
1. Quick Local Execution (Zero-Setup Demo Mode)

Runs immediately out-of-the-box using the bundled SQLite 3.25+ engine:

# Install dependencies
pip install -r requirements.txt

# Run the Flask application
python run.py

Visit http://127.0.0.1:5000 in your web browser.

2. Connecting to MySQL 8.0 (Production Mode)

To connect to an active MySQL database instance, update .env:

DB_ENGINE=mysql
DB_HOST=localhost
DB_PORT=3306
DB_USER=root
DB_PASSWORD=your_password
DB_NAME=sales_analytics_db

Create the database and initialize the schema:

mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS sales_analytics_db;"
python scripts/init_db.py
3. Generating 50,000+ Synthetic Transactions
python scripts/generate_dataset.py --count 50000
4. Running Automated Tests
pytest tests/ -v
